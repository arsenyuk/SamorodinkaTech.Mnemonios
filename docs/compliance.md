# Соответствие законодательству Российской Федерации

Документ описывает, какие нормативные акты РФ поддерживает сервис ЕДИН и каким образом реализовано их соблюдение.

---

## 1. Федеральный закон от 27.07.2006 № 152-ФЗ «О персональных данных»

Основной нормативный акт, регулирующий обработку персональных данных. Сервис ЕДИН обеспечивает соблюдение следующих требований:

| Статья | Требование | Реализация в ЕДИН |
|--------|-----------|-------------------|
| ст. 5 п. 1 ч. 1 | Обработка ПДн осуществляется на основе согласия субъекта | Сервис хранит HMAC-хеши ключей идентификации, не являющиеся ПДн. Полные ФИО, ИНН, СНИЛС хранятся в усечённом нормализованном виде для целей идентификации |
| ст. 5 п. 3 ч. 3 | Обработка ПДн ограничивается достижением конкретных целей | Сервис выполняет исключительно функцию единой идентификации физических лиц (MPI). Не используется для аутентификации, авторизации или иных целей |
| ст. 5 п. 5 ч. 5 | Уничтожение или обезличивание ПДн по достижении цели обработки или по требованию субъекта | `POST /persons/cessation` (мгновенный отзыв) и `POST /persons/cessation/deferred` (отложенный отзыв) обеспечивают полное транзакционное удаление всех данных персоны |
| ст. 14 | Обязанность оператора предоставить субъекту информацию о обработке ПДн | Аудит-лог фиксирует все операции обработки (resolve, cessation) без хранения ПДн; логируются только PersonId и HMAC-хеши |
| ст. 21 | Право субъекта на отзыв согласия на обработку ПДн | Методы `POST /persons/cessation` и `POST /persons/cessation/deferred` реализуют механизм отзыва: мгновенное или отложенное удаление всех персональных данных |
| ст. 6 ч. 1 | Обработка ПДн допускается с согласия субъекта | Сервис не запрашивает и не хранит согласия — это ответственность внешних информационных систем-источников |

### Ограничение: согласие на обработку ПДн

> **Важно.** Хранение согласия на обработку ПДн и отзыв согласия на обработку ПДн **не являются** функциональными особенностями проекта ЕДИН. Эти функции возлагаются на одну или несколько вызывающих корпоративных информационных систем.
>
> ЕДИН предоставляет технический механизм удаления данных (`POST /persons/cessation`, `POST /persons/cessation/deferred`), но **решение о необходимости отзыва** принимает внешняя система-источник на основании собственного учёта согласий. ЕДИН не хранит, не проверяет и не управляет согласиями субъектов на обработку ПДн.

### Ограничение: передача данных через API

> **Важно.** Вычисленные HMAC-хеши **не передаются** через API ни в ту, ни в другую сторону. Персональные данные (ФИО, ИНН, СНИЛС, ДУЛ) **не передаются** вызывающим системам через API — они хранятся в нормализованном виде исключительно для целей внутренней идентификации (ст. 5 п. 3 ч. 3 № 152-ФЗ — ограничение обработки целями идентификации).

### Механизм отзыва согласия (ст. 21)

```
Внешняя система                    ЕДИН
     │                              │
     │  POST /persons/cessation     │
     │  { identifiers: [            │
     │    { sourceSystemId,         │
     │      externalPersonId }      │
     │  ] }                         │
     │─────────────────────────────►│
     │                              │  1. Поиск PersonId по связи
     │                              │  2. Аудит: PersonId + HMAC-хеши
     │                              │  3. Транзакция: удаление ключей →
     │                              │     дефектов → связей → Person
     │  200 OK                      │
     │◄─────────────────────────────│
```

## 2. Федеральный закон от 27.07.2006 № 149-ФЗ «Об информации, информационных технологиях и о защите информации»

| Статья | Требование | Реализация в ЕДИН |
|--------|-----------|-------------------|
| ст. 16 ч. 2 | Обеспечение защиты информации от неправомерного доступа, модификации, уничтожения | PostgreSQL 16 с проверкой CVE по БДУ ФСТЭК (74 уязвимости — все устранены). Все компоненты (.NET 10, ASP.NET Core, EF Core, Npgsql) проверены |
| ст. 16 ч. 3 | Обеспечение конфиденциальности информации | HMAC-SHA256 хеширование ключей идентификации с секретным ключом из .env (не хранится в git). ПДн не логируются |

## 3. Постановление Правительства РФ от 01.11.2012 № 1119

Об утверждении требований к защите персональных данных при их обработке в информационных системах.

| Требование | Реализация в ЕДИН |
|-----------|-------------------|
| Определение уровня защищённости ПДн | Сервис обрабатывает ПДн в усечённом виде (пункт 11 Правил — данные не позволяют идентифицировать субъекта без внешних ключей). HMAC-ключи не являются ПДн |
| Меры защиты от несанкционированного доступа (НСД) | Хранение секретного HMAC-ключа в переменных окружения (.env). DTO-уровень валидации на входе API |

## 4. Приказ ФСТЭК России от 18.02.2013 № 21

Об утверждении состава и содержания организационных и технических мер по обеспечению безопасности ПДн.

| Требование | Реализация в ЕДИН |
|-----------|-------------------|
| Идентификация и аутентификация пользователей | Сервис НЕ выполняет аутентификацию пользователей (вне scope сервиса). Аутентификация внешних систем — TD-002 |
| Контроль доступа к ПДн | Сервис не реализует разграничение доступа (TD-002). Доступ к API открыт только из корпоративного контура |
| Регистрация событий безопасности | Аудит-лог фиксирует все операции через `ILogger` с категорией `Audit.Cessation`. Логируются: PersonId, HMAC-хеши, внешние ID (без ПДн) |
| Защита от вредоносного программного обеспечения | Регулярная проверка компонентов по БДУ ФСТЭК (скрипт `tools/check_fstec.py`). Автоматизация проверки — TD-006 |

## 5. ГОСТ Р 57580.1-2017 «Безопасность финансовых (банковских) операций. Общие требования к защите информации, содержащейся в кредитных организациях»

| Требование | Реализация в ЕДИН |
|-----------|-------------------|
| Идентификация клиентов | ЕДИН обеспечивает единую идентификацию физических лиц для корпоративных систем (CRM, ERP, HR, бухгалтерия) |
| Управление рисками | Валидация ИНН (контрольная сумма — 10/12 цифр), СНИЛС (контрольная сумма — 11 цифр), ДУЛ (неполные данные). Дефекты данных логируются в `person_defects` |
| Резервное копирование | PostgreSQL WAL-архивирование и бэкапы (настройка инфраструктуры — за пределами кода сервиса) |

## 6. Постановление Правительства РФ от 13.09.2024 № 1266

Об утверждении требований к обработке ПДн, осуществляемой с использованием средств автоматизации.

| Требование | Реализация в ЕДИН |
|-----------|-------------------|
| Автоматизированная обработка ПДн | Сервис обрабатывает данные автоматически через API; все операции логируются |
| Ограничение обработки целями | Сервис выполняет только функцию идентификации (MPI) — не используется для иных целей |
| Уничтожение ПДн по требованию | Методы `POST /persons/cessation` и `POST /persons/cessation/deferred` обеспечивают удаление данных по запросу внешней системы |

## Реализация в коде

### Транзакционное удаление (ст. 5 п. 5 ч. 5, ст. 21 № 152-ФЗ)

```csharp
// PersonRepository.DeletePersonDataAsync
await using var transaction = await _context.Database.BeginTransactionAsync();
try
{
    _context.PersonIdentificationKeys.RemoveRange(keys);
    _context.PersonDefects.RemoveRange(defects);
    _context.PersonExternalIds.RemoveRange(externalIds);
    _context.Persons.Remove(person);
    await _context.SaveChangesAsync();
    await transaction.CommitAsync();
}
catch
{
    await transaction.RollbackAsync();
    throw;
}
```

### Аудит без ПДн (ст. 14 № 152-ФЗ, ст. 21 № 21-приказа ФСТЭК)

```csharp
// PersonCessationService.LogCessationAudit
_logger.LogWarning(
    "[Cessation] PersonId={PersonId}, Identifiers=[{Identifiers}] | Keys: [{Keys}] | ...",
    personId, string.Join(", ", request.Identifiers.Select(i => $"{i.SourceSystemId}/{i.ExternalPersonId}")), ...);
// Логируются: PersonId (GUID), HMAC-хеши, внешние ID — НЕ ФИО/ИНН/СНИЛС
```

### Защита HMAC-ключа (ст. 16 ч. 3 № 149-ФЗ)

```json
// appsettings.json

  }

// .env (не в git)

```
